# ranypia Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]` checkboxes.

**Goal:** An R package reproducing pyanypia 0.3.0's benefit-formula functions to the cent, with tidyverse-friendly inputs and outputs.

**Architecture:** Vectorized matrix arithmetic in R mirroring pyanypia module by module. The tidyverse is used only at the edges: tibble outputs, long earnings via tidyr, and rlang/cli errors. Exactness is proven against JSON fixtures that pyanypia generates.

**Tech stack:** R ≥ 4.0, tibble, dplyr, tidyr, rlang, cli, vctrs, jsonlite (tests only), testthat 3e, roxygen2. Fixtures come from Python 3.11+ with pyanypia installed from `/Users/anthony/pyanypia`.

**Spec:** `docs/superpowers/specs/2026-10-04-ranypia-design.md`

**Behavioural spec:** for every task, the named pyanypia module, at `/Users/anthony/pyanypia/src/pyanypia/`, is the reference. Port its operation order and rounding exactly, and keep docstrings as roxygen comments.

## Global constraints

- Exactness: `expect_identical()` on every money value from the fixtures.
- Fixed summation order (explicit loops) wherever pyanypia loops. Never use `sum()` on money that must match bit for bit.
- Every `%%` that stands in for C's `fmod` goes through the `fmod()` helper.
- Errors use `rlang::abort()` with the field name, the count of bad rows and the first bad row (1-based).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Confirm with the user before creating the GitHub repo or tagging.
