# ranypia — design

Date: 2026-10-04
Status: approved in conversation

## Why

The user wants pyanypia's benefit-formula functions in R, for hypothetical
examples and microsimulation, with the same exactness. ranypia is a
standalone package: `anthonycolavito/ssmbar` (whose analytical R scripts the
user maintains themselves) is not touched.

## Decisions

| Question | Decision |
|---|---|
| Home | New public repo `anthonycolavito/ranypia`, package `ranypia` |
| Scope | Everything in pyanypia 0.3.0 |
| Implementation | Native R port of pyanypia; arithmetic as vectorized matrix math |
| Tidyverse | Allowed: tibble outputs, long or wide earnings, data-frame inputs, rlang/cli errors |
| Testing | testthat against fixtures generated by pyanypia (penny-exact vs anypia-engine) and committed to the repo; no Python needed to run tests |
| R version | `Depends: R (>= 4.0.0)` (the user has 4.0.3); the package does not use `|>` internally |

## Behavioural spec

pyanypia 0.3.0 (`src/pyanypia/*.py`) is the behavioural spec: each R
function reproduces the Python function of the same name, including
operation order and rounding. Where R and Python differ:

- `%%` is not C's `fmod`; rounding uses a faithful `fmod` (`x - trunc(x / y) * y`
  is checked against fixtures).
- Sums that must match bit for bit (AIME totals, bracket sums, family
  totals) loop in a fixed order, never `sum()`.
- Integer-valued inputs are stored as doubles or integers as convenient;
  validation rejects fractional values where whole numbers are required.

## Interface

- Functions: `eligibility_year`, `normal_retirement_age`,
  `earliest_claim_age`, `early_reduction_factor`, `spouse_reduction_factor`,
  `delayed_credit_factor`, `benefit_factor`, `monthly_benefit`,
  `adjusted_birth`, `cola_year`, `capped_earnings`, `indexed_earnings`,
  `elapsed_years`, `computation_years`, `aime`, `quarters_of_coverage`,
  `fully_insured`, `disability_insured`, `years_of_coverage`, `bend_points`,
  `family_max_bend_points`, `pia`, `family_max`, `apply_colas`,
  `special_minimum_pia`, `di_family_max`, `childcare_aime`, `auxiliary`,
  `family_benefits`, `wep_pia`, `gpo_offset`, `retired_worker`,
  `disabled_worker`, `deceased_worker`, `widow_guarantee_pia`.
- Earnings: a numeric matrix (rows = workers; columns named by year, or
  `first_year =`), a named numeric vector (one worker, names = years), or a
  long data frame with `id`, `year`, `earnings` (converted by the exported
  `earnings_matrix()` with tidyr; results keep the `id` order).
- People: vectors, or for the one-call helpers a data frame `people` whose
  columns supply `birth_year`, `birth_month`, `birth_day`, `claim_age`, etc.
  (explicit arguments win).
- Ages in months from the adjusted birth month, as in pyanypia.
- `policy` last everywhere, default `current_law()`.

## Policy

`current_law(alt = 2)` returns a `ranypia_policy` (S3 list) holding the
primitive fields of pyanypia's `Policy` plus all derived series, computed
eagerly at construction and indexed by `year - 1936` (1937..2105).
`policy_replace(policy, ...)` rebuilds from changed primitives;
`policy_with_series(policy, name, values)` pins derived values. A print
method summarises the policy. Validation mirrors pyanypia.

## Outputs

- Scalar functions return numeric (or logical) vectors.
- `retired_worker()`, `disabled_worker()`, `deceased_worker()` return a
  tibble, one row per worker, columns `id` (when known), `elig_year`,
  `aime`, `pia_elig`, `pia`, `mfb`, `nra`, `factor`, `benefit`, `method`,
  `insured`.
- `family_benefits()` returns a long tibble: `family`, `member`, `kind`,
  `full`, `after_max`, `reduction_factor`, `benefit`.

## Errors

`rlang::abort()` with cli formatting; messages match pyanypia's
("earnings: negative in 2 row(s); first at row 3"; rows 1-based in R).

## Data

The 2026 Trustees Report series go in `R/sysdata.rda`, generated from
pyanypia's `_data2026.py` by `data-raw/make_sysdata.py` (or an R script
reading a JSON export).

## Testing

1. `tools/make_fixtures.py` (run with pyanypia installed) writes
   `tests/testthat/fixtures/*.json`: policy series for alternatives 1-3,
   unit-level cases for each function, and random-worker sweeps (retired,
   disabled incl. child-care, survivors with widow guarantee, life families,
   WEP) with pyanypia's outputs.
2. testthat compares every value exactly (`expect_identical` on doubles).
3. Vectorized vs one-at-a-time equality for each one-call helper.
4. Long-format and data-frame inputs give the same results as matrices.

## CI and release

GitHub Actions `r-lib/actions/check-r-package` on ubuntu, macOS, Windows
(release R) and ubuntu with R 4.0. Public repo created and v0.1.0 tagged
only after the user confirms. README covers install
(`remotes::install_github("anthonycolavito/ranypia")`), a quickstart, a
microsim example on long panel data, policy/reforms, scope (same as
pyanypia), and testing.
